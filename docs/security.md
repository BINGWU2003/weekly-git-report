# 安全与隐私

Weekly Git Report 是本地单用户工具，但仍会处理仓库凭据、提交内容、AI API 密钥和飞书 Webhook。本页说明系统当前提供的保护、发送到外部服务的数据，以及用户仍需承担的边界。

## 本地优先

- 配置、仓库缓存、运行数据库、采集数据和报告正文默认保存在本机。
- 仓库同步使用系统 Git 与本机已有凭据，不把 Git 凭据交给应用层保存。
- 报告浏览和最新提交状态默认读取本地缓存，不通过 GitHub 或 GitLab API 查询。
- 只有生成报告时会把脱敏输入发送给所选 AI 供应商；只有明确要求时才向飞书发送报告。

## 密钥存储

AI API 密钥、飞书 Webhook 和签名密钥保存在 `~/.weekly-git-report/ai.json` 与 `feishu.json`。

- Windows 会移除继承权限，并将文件访问限制为当前用户 SID。
- macOS 和 Linux 使用 `0600` 文件权限。
- 密钥不会写入普通日志。
- Desktop 状态接口只返回掩码；用户明确点击查看某一字段时，才通过受限 IPC 读取该字段明文。
- 保存其他设置时，未修改的敏感字段保持原值。

这些文件不是系统 Keychain、Credential Manager 或 DPAPI 密文。能够以当前系统用户身份读取文件的进程仍可能访问其中的密钥，应保护操作系统账户和本地备份。

## 发送给 AI 的数据

结构化 `generationInput` 默认包含：

- 仓库 ID、名称和分支。
- 提交哈希、提交时间、标题、正文和作者姓名。
- 用户填写的补充背景。
- 报告类型、日期范围和标题。

它不会专门包含：

- 作者邮箱。
- 仓库远程 URL。
- 本地文件路径。
- 代码 Diff。
- Git 凭据或应用密钥。

提交标题、正文和补充背景按事实原样进入生成输入。如果这些文本本身包含邮箱、内部地址、密钥或其他敏感数据，它们不会被通用规则可靠移除。用户应在配置 AI 前理解这一点，并在报告草稿中再次审核输出。

## Prompt Injection 边界

Git 提交标题、正文和用户补充背景都被视为不可信数据，而不是系统指令：

- 内置 AI 使用固定系统约束区分模板、事实和提交文本。
- MCP 与 Skill 明确要求宿主只把 `template` 当作生成规则，把 `generationInput` 当作事实来源。
- 外部 Agent 不应读取 Raw、manifest 或 Run 路径来绕过脱敏边界。
- 报告生成不得虚构输入中不存在的事实。

这些规则降低了提交文本改变生成行为的风险，但不能替代用户审核。包含恶意或误导性文本的仓库仍可能影响生成质量。

## Git 与仓库安全

- 仓库 URL 不允许内嵌密码或 Token。
- 私有仓库认证完全交给系统 Git、SSH Agent 或系统凭据管理器。
- 已有缓存仓库必须拥有与配置一致的 `origin`。
- 同步只获取配置分支并使用 `--filter=blob:none`，不需要读取完整文件内容。
- 删除缓存前会拒绝磁盘根目录、用户目录、工作目录、缓存根目录和符号链接等危险目标。

## Electron 边界

Desktop Renderer 运行在沙箱中，不直接获得 Node.js 能力：

1. Preload 使用 `contextBridge` 暴露固定的 `window.electronAPI`。
2. IPC channel 采用白名单注册。
3. Main handler 对来自 Renderer 的输入做 Schema 或显式参数校验。
4. 文件、Git、SQLite、密钥和网络操作只在主进程中执行。
5. AI 流式内容和更新状态通过受限事件回调返回 Renderer。

这限制了界面代码可以直接访问的本地能力，但用户仍应只安装可信来源的正式构建。

## 路径和文件完整性

- 所有 Raw、Summary、历史和回收站操作都必须位于配置的报告目录内。
- 保存前校验 generation input 哈希、模板 revision 和 Raw manifest 哈希。
- Sidecar 保存 Markdown 内容哈希和生成来源。
- 飞书推送前重新读取并校验 Sidecar 与正文哈希。
- 飞书接口不能发送任意字符串或任意本地文件，只能发送有效 Run 对应的已保存报告。

`force` 只允许在用户确认后覆盖关联信息异常的既有报告，不能绕过 Raw 或 Run 来源完整性校验。

## 飞书发送边界

- 配置并通过连接测试不等于获得每次发送授权。
- 手动生成、CLI、MCP 和 Skill 只有本次明确要求推送时才发送。
- 报告任务通过独立的“保存后推送飞书”选项授权。
- 推送失败不会删除本地报告。
- 消息超过飞书卡片大小限制时直接失败，不会静默截断报告。

## 更新边界

自动更新只在 Windows x64 正式安装包中启用，通过固定 GitHub 仓库的 stable Release 获取元数据。应用不会自动下载；用户确认下载后，可以选择立即安装或退出时安装。报告正在生成、保存或推送时会阻止安装。

首版安装包可能没有代码签名，系统可能显示来源警告。发布资产提供 `SHA256SUMS.txt` 供人工校验。

## 用户责任

- 使用专门的低权限 AI API 密钥和飞书机器人。
- 不在 Git 提交或补充背景中放入密钥。
- 审核 AI 草稿后再保存或推送。
- 保护本地账户、报告目录和备份。
- 定期检查仓库与飞书权限，撤销不再使用的凭据。
